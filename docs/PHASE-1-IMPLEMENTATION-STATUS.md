## How the site is built

Every page in `site/*.html` is generated by `python3 tools/build_pages.py` from
`tools/kit.py`, `tools/pages_core.py` and `tools/pages_guides.py` (needs Pillow). Edit
those, not the HTML: the next build overwrites hand edits. The earlier phase 1 commits
edited the HTML directly, which is what caused the 22 merge conflicts with `main`. CI now
fails if `site/` differs from the builder's output.

The analyser is built from `analyser/` with `npm run build`, which writes
`site/analyser/index.html`. CI checks that too.

## What changed

- **Sample report** (`sample-report.html`): a made-up office, every figure taken from the
  analyser's output for `site/samples/example-office.csv` at 25p/kWh. The closed-hours
  cost (£2,776) is shown once; bank holidays and early/late use are marked "already
  included"; base load (about £5,700) is shown as separate; and a section explains that
  these are costs, not promised savings. A unit test fails if the analyser and the page
  ever disagree.
- **Home page** links to the sample report beside the main "Analyse my data" button.
- **SEO**: absolute canonical and `og:url`/`og:image` on every indexable page, generated
  `sitemap.xml` (25 URLs) and a `Sitemap:` line in `robots.txt`. `thanks.html` and
  `404.html` are `noindex`, carry no canonical and are not in the sitemap.
- **Contact page**: email fallback under the form (the form already posts to Formspree).
- **Privacy notice**: names Formspree, says it may process data outside the UK, and
  states retention as criteria (kept only as long as needed, then deleted from email and
  Formspree) rather than a fixed period nobody has agreed.
- **Accessibility**: the analyser's file upload now has an accessible name.
- **Images**: the 25 approved images are `main`'s native JPG/PNG files with their small
  srcset variants. The base64 SVG wrappers in `site/images/phase1/` and the CI workflow
  that committed to the branch were removed.

## Moving to the final domain

Change `SITE_URL` in `tools/kit.py`, run `python3 tools/build_pages.py`, commit. That
updates every canonical, share link, structured-data URL, the sitemap and robots.txt.
There is no other hard-coded address. Then add the domain in Netlify, redirect the
`netlify.app` address to it, and submit the sitemap in Search Console.

## Rollback

Releasing means merging PR #9 into `main`; Netlify then deploys it.

- Fastest: in Netlify, Deploys, open the last deploy before the merge and choose
  "Publish deploy". The old site is back within a minute or so, with no code change. If
  Netlify then shows auto publishing as locked, unlock it once the fix is on `main`.
- To make it permanent: `git revert -m 1 <merge commit>` on `main` and push.
- This release changes no Netlify settings, DNS or stored data, so rollback has no side effects.
